## 01 今回の結論

最初の60日は、集客の入口を「新規開業またはサイト未整備の、小規模なリフォーム・外構施工会社」に集中する。静的な会社紹介・施工例・相談獲得サイトを提案し、商談で必要な情報量に応じて55,000円または110,000円の既存プランを使う。

他業種の相談受付と、既存サイトの制作体験は維持する。すべてのサービスを一業種専用に作り替えることは提案しない。広告、記事、業種別ページを一つの顧客像に合わせる。

媒体の優先順位は、自社サイトの業種別ページと記事 → Instagram → 計測条件が揃ってからGoogle検索広告。LINEとメールは相談の受け皿として運用する。最初からX、LinkedIn、note、YouTube、広告を同時に増やさない。

自動化の本体はGitHub Actionsを初期推奨とする。今の静的サイトと公開GitHubを使えるため、n8n Cloudの新規契約を開始条件にしない。記事・SNS・計測の連携が増え、運用画面で管理したくなった段階でn8nを再評価する。

予算は初月のツール枠5,000円以内、広告0円から開始。業種ページ・実受信・計測を確認できたら、次の30日で検索広告20,000円の検証枠を提案する。これは事業側の推奨予算上限であり、サービスの最新価格や市場相場ではない。

### 最新情報の確認範囲

## 02 業種を絞る範囲

絞るのは「最初に誰に何を伝えるか」。問い合わせ受付は事業用の静的サイトに合う他業種も残す。Builderの業種を削除したり、既存のコピーや生成ルールを変更したりする必要はない。

対象像は、会社情報がSNSだけ、古いサイトがスマホで読みにくい、施工例や対応エリアが伝わっていない、小規模な施工会社。決裁者が明確で、原稿・施工写真を支給でき、予約や顧客管理は既存の外部サービスで足りる案件を優先する。

最初の訴求は「会社の強みと施工例を整理し、スマホから相談しやすいサイトへ」。検索順位や受注数の保証、施工会社の事業成果を自社制作の確定成果として約束しない。

### 比較した業種

下記は標準サービスとの相性を評価した定性比較。市場シェア・検索数・成約率のランキングではない。

| 対象 | 標準範囲との相性 | 注意点 | 初期判断 |
| --- | --- | --- | --- |
| 小規模リフォーム・外構 | 高い。会社紹介、施工写真、対応地域、相談フォームが中心 | 写真と施工実績の利用許可、実際の対応地域を確認 | 主力候補 |
| 売却・管理特化の小規模不動産会社 | 高め。静的な業務紹介と相談導線なら対応可能 | 物件掲載DB・検索・頻繁な自己更新を希望すると別見積り | 次点 |
| 独立した美容室・小規模サロン | 高い。写真、メニュー、地図、外部予約が使える | 既存予約媒体との役割、低価格競争、継続するメニュー更新 | 他業種の受付候補 |
| 小規模な士業事務所 | 高め。説明・信頼情報・相談が中心 | 専門情報の支給、職種ごとの表示や広告の確認が必要 | 得意分野ができたら検証 |

| 物件ポータル・EC・会員/独自予約 | 低い。標準外のシステムが必要 | データ管理、決済、運用・保守の範囲が増える | 個別見積りのみ |

### 昨夜の不動産中心の仮案を変更する理由

GARAGE HOUSE NAVIは自主制作の説明材料として有効だが、一般的な不動産会社へそのまま訴求すると、物件検索・掲載データ・自己更新まで期待される可能性がある。低価格の静的サイトとして受ける際の認識差を減らすため、施工会社の会社紹介・相談獲得を主力にする。

不動産は、売却相談・管理相談・会社案内など目的を狭めれば次点として有力。既存の自主制作を受託実績に見せないこと、実装する検索システムを基本料金に含むと誤解させないことを前提にする。

工務店向けの制作体験は既にあるため、既存の機能を保ちながら案内をつなげられる。施工会社の受託実績があるわけではないので、最初は明記した制作サンプルと、実際の自主制作例で説明する。

Instagramは、制作物を視覚で説明できることを理由に選ぶ初期仮説。小規模施工会社の意思決定者に届く利用率を今回実測したわけではない。30〜60日の有効相談で評価する。

### 投稿内容

1. 会社情報だけのサイトから、施工例・対応エリア・相談の流れを見つけやすくする説明図。
2. 工務店向けの制作体験。架空のページは「制作サンプル」と明記。
3. サイト制作前に支給してほしい写真・会社情報・原稿のチェックリスト。
4. 1ページと5ページまでのプランの違い。料金・2週間の開始条件を明記。

同じ記事から2投稿を作り、記事→業種ページ→制作体験/相談へつなぐ。フォロワー数や「いいね」だけで受注効果を判断しない。リールは静止画投稿の反応と制作負担を見て追加する。

### 記事の最初の4本

・リフォーム会社のホームページに必要な情報と、素材準備チェックリスト。
・施工事例を載せるときに確認したい写真・掲載許可・個人情報。
・1ページと複数ページ、会社紹介と相談獲得にはどちらが合うか。
・ホームページ制作の見積りで比較する範囲・修正・維持費・納期。

記事数や文字数を目的にしない。事実マスターと支給情報から判断材料を作る。施工会社の専門的な工事価格や施工保証は、情報を確認せずAIで説明しない。

## 04 広告を始める条件

先に業種別ページ、料金・標準範囲、メールの実受信、LINEの受信/返信、計測を確認する。広告のクリックを「有効な問い合わせ」として数えない。

広告はホームページ制作を検討する事業者の意図に限定して試す。「外構工事 見積り」など、施工を依頼したい消費者の意図とは分ける。具体的な検索語・地域・ボリューム・単価はGoogle広告のツールで確認するまで未確定。

全国の「ホームページ制作」だけを広く狙う初期案にはしない。実際に使える対面対応や地域知見があればその地域を使う。オンラインで全国対応する場合は業種・目的で絞り、同じ本文に地域名を付けたページを量産しない。

初回は30日で20,000円を検証枠とする。これは最適な広告単価の実測結果ではない。予算・期間・停止条件は所有者が確定してから課金する。媒体の予算仕様を確認し、日予算を厳密な毎日の支出上限と誤解しない。

### 判断に使う計算

広告による成約獲得費の式は「クリック単価÷（有効相談率×成約率）」。下記は計算例で、市場相場・予測・目標達成の保証ではない。

| 仮定 | 計算結果 | 意味 |
| --- | --- | --- |
| クリック300円、有効相談率3％、成約率20％ | 1成約あたり50,000円 | 55,000円の制作に工数と実費が加わると余裕が小さい |
| クリック150円、有効相談率3％、成約率25％ | 1成約あたり20,000円 | 良い条件を仮定した場合でも、工数・実費・税を確認する |

20,000円の広告枠は、少数のクリックや相談にとどまる可能性がある。1か月で大量の反響を得る計画とはしない。計測不良、対象外の検索意図、相談先の障害は直ちに停止・修正する。少数の相談だけで業種の需要がないと断定しない。

商談の主力は、情報量に合う場合の110,000円プランを検討する。1ページで足りる相手に複数ページを押しつけない。広告のために料金を無断で値上げしない。

## 05 推奨予算

各額は事業側で設ける月の枠。n8n、Buffer、AIモデル等の最新料金を確認した見積書ではない。無料枠、年払い、為替、税、API対応、従量課金を導入時に確認する。

| 項目 | 初月の枠 | 次の30日の枠 |
| --- | --- | --- |
| AI API | 2,000円以内 | 2,000円以内 |
| SNS連携/予約ツール | 2,000円以内。必要な公式連携が使える場合だけ契約 | 2,000円以内 |
| GitHub実行等の予備 | 1,000円以内。実際の課金条件を確認 | 1,000円以内 |
| Google検索広告 | 0円。基盤と計測を先に確認 | 条件が揃った場合20,000円 |
| 合計 | 5,000円以内 | 25,000円以内 |

既に取得したドメイン費用と、所有者の作業時間はこの枠と別。上記の枠で対応するツールやAPIが使えなければ、機能を減らす・別手段を検討し、無断で契約を増やさない。

GitHubの対象リポジトリは公開で、既存のPagesは稼働している。だからといってすべてのActions実行・ランナー・APIが無料とは確定しない。契約と実行環境の課金条件を確認する。

AIの費用は、選んだモデルの実単価とトークン量、生成回数、検査回数で管理する。課金画面の予算設定が通知だけの場合は、自動処理側でも回数・トークン・月の使用量に基づく停止を設ける。通知だけで厳密な上限が守れるとは扱わない。

最低限は、AI APIと既存GitHubだけで記事の下書き・検査・公開の自動化を作る。SNS連携が未確認の間は、下書き保存まで稼働し、投稿成功や全自動稼働を装わない。

## 06 自動化ツールの吟味

| 構成 | 利点 | 負担・条件 | 判断 |
| --- | --- | --- | --- |
| GitHub Actions＋固定スクリプト | 既存の静的サイトに近い。公開版とログを追える | 初期実装、API接続、実行制限、障害通知が必要 | 初期推奨 |
| n8n Cloud | 台帳や業務連携を画面で管理しやすい | 新しい契約費用、実行量、資格情報、外部サービスへの送信 | 連携が増えたら採用を検討 |
| n8nの自己ホスト | 自由に構成できる | サーバー、更新、バックアップ、障害対応を本人が持つ | 初期は推奨しない |
| Buffer等の予約サービス | SNSの予約・管理をまとめやすい | 希望する媒体/投稿/APIがそのプランで利用できるか未確認 | 条件を確認できたら採用 |
| Meta公式の投稿連携 | Instagramを直接接続する選択肢 | アカウント種別、権限、アプリ設定/審査、認証期限を確認 | 自動投稿の第一候補として検証 |

初期は「GitHub Actionsを本体、Instagramの公式対応経路を1つ」にする。Bufferを使えば必ず外部システムから全自動投稿できると決めつけない。導入時にAPIへのアクセスと投稿種別が確認できなければ契約しない。

Metaの公式予約画面は手動で予約する補助として使えるか確認する。AI生成→予約枠への自動登録とは別の機能なので、完全自動化の稼働確認には含めない。

最初の自動化は「記事1本/週、記事からSNS2案、品質ゲート、許可した記事パスへの公開、公開結果確認、週次集計」。GmailやLINEの相談全文を自動でAIへ送る連携は、この初期構成に含めない。

## 07 アカウント接続の推奨

すべて所有者本人のアカウントを基本とする。複数の運用者を追加する場合は招待で権限を渡す。パスワードやAPIキーをチャット・公開GitHubへ貼らない。

| アカウント/サービス | 今の状態 | 接続するもの | 優先 |
| --- | --- | --- | --- |
| GitHub | リポジトリ・Pagesを確認済み。集客の定期処理は未実装 | 記事生成/検査/公開のActions、最小権限の認証 | 最初 |
| Google Search Console | 登録リクエスト済みという所有者の報告。実際の掲載は未確認 | pageatelier.jp、実際のインデックス確認。集計APIは別接続 | 最初 |
| GA4 | サイトに未導入 | 所有者のプロパティ、Webストリーム、計測、説明の更新 | 広告より先 |
| LINE公式 | アカウントURLと3つのボタンを設定済み | スマホで受信/返信/通知。Messaging APIは当面不要 | 最初 |
| Instagram | 開設・接続の報告なし | ビジネス用のプロフェッショナルアカウント、公式連携 | 最初のSNS |
| Metaの管理/開発設定 | 未接続 | 投稿経路が必要とするページ連携・権限・アプリ設定等 | 自動投稿の実装時 |
| AI API | この案件での接続は未確認 | 本人のAPI請求設定、選んだモデル、GitHubの安全なSecrets | 自動生成の実装時 |
| Google広告 | 接続・出稿は未確認 | 所有者の広告アカウント、課金、対象と期間、コンバージョン | 基盤確認後 |
| Buffer | 未契約・未接続 | 対応プランとAPIを確認後、本人のOAuth等で接続 | 必要な場合のみ |
| n8n | 未導入 | 非公開台帳など業務連携が増えた場合に再検討 | 後回し |

Googleは、問い合わせを管理している本人のアカウントから所有権を管理するのが初期案。サイト上の受信先 eyu.eyu0806@gmail.com は維持する。Googleのログインと、実際の問い合わせ受信先が同じである必要はないので、所有権のあるアカウントを確認して使う。

Instagramの表示名は「サイト工房｜Page Atelier」を候補とする。ハンドルは `pageatelier_studio` 等が候補だが、空きは確認していない。公式LINEとサイトの名称・ロゴ・URLを揃える。

AIはOpenAI APIを第一候補にする。文章用の小〜中規模モデルを、実際の単価・文章品質・出力形式で選ぶ。最新モデル名や最安価格は今回未確認。ChatGPTの利用契約とAPI課金を同じものと扱わない。

GitHub ActionsのAPIキーはGitHubのSettings → Secrets and variables → Actions等、正式な管理画面で保存する。一般的な実装ではAPIキーをSecretsに入れ、ワークフローから参照する。公開したリポジトリに平文で置かない。外部PRや生成原稿に秘密情報・公開権限を渡さない。

GoogleやMetaへの接続はOAuth等の正式な権限許可で行う。集計に顧客の名前・メール・相談全文を送らない。認証期限、解除、費用、停止操作を所有者が把握できる記録を残す。

## 08 60日間の実施順

### Day 1〜7：受け皿と接続

LINEの実受信・返信を確認し、Search Consoleの実際の掲載状況を確認する。GA4等の計測を、現在の説明・必要な同意と合わせて導入する。施工会社向けの業種ページを1つ用意する。既存の構造・生成・フォームを保つ。

Instagramを開設または既存アカウントへ接続する。掲載できる素材と、制作サンプル/自主制作の表示を揃える。広告はまだ開始しない。

### Day 8〜30：記事・SNS・自動化の検証

週1記事と週2投稿を初期案として作る。最初の3記事を確認して固定ルールを調整し、通常記事の予約公開へ進める。公開対象パス、価格・納期・範囲、リンク、重複、停止操作を検証する。

実際の公開URL、投稿ID、期間、問い合わせ経路を記録する。Instagramの全自動接続が未完了なら、下書きまでの稼働と明記する。未公開の投稿を投稿済みにしない。

### Day 31〜60：少額広告と判断

実受信・計測・業種ページが確認できた場合に検索広告を30日・20,000円の枠で検証する。検索語と有効相談を照合し、対象外の意図は修正する。費用や範囲が合わない場合は広告を保留する。

目標は大量問い合わせではなく「どの入口から、どんな有効相談が来るか」を知ること。訪問/クリックと実相談を区別する。記事の検索流入はこの期間に十分出ない可能性があり、短期の数字だけでSEOが失敗したと決めない。

有効相談があり、対応工数と受注条件が合えば主力を継続する。相談はあるが物件検索など標準外ばかりなら訴求と対象を修正する。十分な露出・正しい計測がない場合は、業種を変える前に媒体・ページ・配信を確認する。

## 09 判断を変える条件

・知人や既存の顧客接点が特定業種にある場合は、業種の順位よりその接点を優先する。
・対象の施工会社が必要とする更新機能や写真準備が標準に合わない場合は、別見積りか対象の変更を考える。
・不動産の売却/管理の静的サイトへ実相談が集まるなら、次点を主力へ変更できる。
・Instagramで実際の対象に届かず、他媒体に接点があるなら媒体を変更する。フォロワー数だけで維持しない。
・広告の相談単価と制作工数が合わなければ、停止して提案・範囲・集客方法を見直す。
・確認した外部料金が予算枠に収まらない場合は、機能と運用を減らして再設計する。

広告・記事に費用が掛かっても、受注が保証されるわけではない。少数データの計算例を市場の予測値として扱わない。仕事を多く受ける前に、2週間工程を守れる同時進行数と返答できる時間も確認する。
